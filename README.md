# Game: Zombie Revolution — SQL Case Analysis

Кейс: комплексный анализ мобильной игры «Zombie Revolution» в период маркетинговой акции.  
Цель: оценить вовлечённость, технические проблемы, эффективность маркетинга, финансы и виральность.

Данные: учебный датасет (платформа [Название]), доступ истёк.  
Решение: SQL-запросы, разбитые по ключевым бизнес-задачам (см. папку `queries/`).  
Результаты и выводы: финальная презентация с графиками и рекомендациями (см. папку `presentation/`).

## Структура решения по задачам

1. **Общие метрики** (`queries/01_basic_metrics.sql`) — DAU/MAU, сессии, средняя длительность.  
2. **Маркетинг и MAU** (`queries/ 02_ DAU_WAU_MAU_metrics.sql `) — влияние акции на активность.  
В папке queries представлены SQL-скрипты для расчёта DAU/WAU/MAU.
Для финальной сборки метрики Sticky Factor использован комбинированный подход:
SQL-скрипт (02_ DAU_WAU_MAU_metrics.sql) содержит корректный расчёт метрики по формуле (средний DAU / WAU/MAU) для верификации данных.
•	Финальный расчёт и визуализация графика выполнены в Excel для удобства презентации
3. **Техпроблемы** (`queries/03_tech_issues.sql`) — Анализ технических сбоев:
   - доля незавершённых сессий (`end_session IS NULL`) от общего числа;
   - доля сбоев внутри каждой платформы (iOS/Android);
   - распределение платформ среди всех проблемных записей. 

   Данные объединены через `JOIN game_sessions` и `users`, логика разбита на 3 прозрачных блока.

4. **Покупки клиентов и популярность продуктов** (`queries/04_purchases_and_popularity.sql`) — выручка, изменение цен на кристаллы.  
5. **Покупки клиентов по когортам – анализ «щедрости»** (`05_purchases_in_cohorts.sql`) – выручка по клиентам в зависимости от принадлежности разным когортам. На каких пользователей активнее нацеливать маркетинговые акции.
6. **K-factor** (`queries/06_k_factor.sql`) — вирусность игры и реферальная программа.  
7. **Лояльные пользователи** (`queries/07_loyal_users.sql`) — определение лояльности и динамика по месяцам.
